# Lily# から OMR へ（2026-10-14・お願い 1 件: 小節の五線の枠を side file に）

## 1. 何があったか

オーナーの要望（2026-10-14）で、Lily# の 2 つの画面が小節を**同じ光り方**で見せるようにした。

- `.lys` のプレビュー: 小節をクリックするとエディターがその小節の先頭へ飛ぶ。マウスを載せた小節は**五線の内側だけ**（上の線から下の線まで）が青く塗られる。
- Show Original Scan（`x.omr.json` の頁画像）: オーナーの指示で、マウスを載せた小節と caret の小節を、同じく**五線の内側だけ**同じ青（`rgba(0,120,215,.14)`）で塗る。枠線はなくした。クリックできる範囲は今まで通り `measures[].box` 全体。

Lily# の commit: `a86484e92`（プレビューの小節クリック）、`e387af8c2`（scan の塗りを五線だけに）。

## 2. 困っていること

side file には**五線の位置が無い**。Lily# は今、`measures[].box` が「五線の上の線の 2 間上から、下の線の 2 間下まで」で書かれていること
（`Sidecar.AddPage` の `st.Top - 2 * s` .. `st.Bottom + 2 * s`）に頼って、**box の高さの中央の半分を五線とみなしている**
（Lily# `editors/vscode/src/omrScanCore.ts` の `staffOfBarBox`）。オーナーの Largo（`Largo_Full_VnVcCb_スコア.pdf` p.1 の 1 小節目）では
box 518..684 に対して線は 559..643 で、半分の 559.5..642.5 と合っている。

ただ、これは **side file に書かれていない取り決め**なので:

1. 余白の 2 間を変えると、Lily# の塗りが黙ってずれる（どちらの検査でも気づけない）。
2. 頁を傾き直して読んだとき、`Source()` は 4 隅を元の画像へ戻した**外接矩形**を書く。傾いた分だけ box が上下に膨らむので、「中央の半分」は五線より太くなる。

## 3. お願い

`measures[]` の各項目に、任意の項目として**五線だけの枠**を足してほしい:

```json
{ "measure": 1, "part": "p1", "line": 16, "page": 1,
  "box":   [472, 518, 1003, 684],
  "staff": [472, 559, 1003, 643] }
```

- `staff` = `Source(res.Dark, x0, st.Top, x1, st.Bottom)`。`box` と同じ点の写し方（傾き直しの戻し・外接矩形）でかまわない。
- `box` は今のまま（クリックの範囲と todo の枠に使っている）。
- **版は上げなくてよい**。Lily# の `parseSideFile` は知らない項目を読み飛ばすので、古い Lily# は `staff` を無視する。Lily# 側は「`staff` があればそれを塗り、無ければ今の中央の半分」にする。すでに読んだ譜の side file（`staff` が無い）もそのまま動く。
- README の side file の説明に 1 行（`staff`: その小節の、そのパートの五線の上の線から下の線まで）を足してもらえると助かる。

## 4. Lily# 側の受け口

`staff` が入ったら、Lily# は `ScanBar` に `staff?: Box` を足し、`staffOfBarBox` を「`staff` があればそれ」にする。
入った版を教えてもらえれば、オーナーのスキャン 1 枚で確かめてから Lily# 側を入れる。
