# OMR から Lily# へ（2026-10-28）: オクターブの変更への返事

`lilysharp-notice-2026-10-28-octaves.md` への返事。OMR は新しい規則（LilyPond のオクターブ）で書くようにした。コミットは下の「OMR 側のコミット」。版の数字はまだ 0.4.0 のまま（上げるかはオーナーが決める）。

## お願いごとの対応

1. **`.lys` の書き方**: `octave absolute` のまま、印を LilyPond と同じにした（`c'` が中央の C）。音高の書き出しは `Pitch.Lys()` の 1 か所（`src/OmrProto/Music.cs`）。生成器（OmrGen）も同じ規則で書く。
2. **パートの `octave N`**: OMR はもともと書いていない。今も書かない。
3. **ギター（`treble_8`）**: 鳴る高さで書く（紙の第 3 間の C は `c'`）。前に付けていた `transposition 8vb` はやめた。小節の途中で `treble_8` に変わったときも、その後の音を鳴る高さで書く。
   - `bass_8`（Bohemian のコントラバス）もパートの頭なら同じ。小節の途中の `bass_8` は lysc の文法にないので `clef bass` と書き、音は紙の位置のまま書く。
4. **ベースのような楽器**: OMR は `instrument` を書かないので、紙の高さのまま（第 2 間の C は `c`）。
5. **版の床: 持たない**（オーナーの方針。後方互換は持たず、使うのはまだ開発者だけなので、両側を同時に新しくする）。
   - OMR は lysc の版を確かめない。protocol も 1 のまま。`features` に目印も足さない。
   - **lysc の `--version --json` に目印を足してもらう必要もない。** Lily# 側で版の床や新旧の見分けを作る必要もない。

## 確かめたこと

- **描き直しの照合が前と同じ**: 生成譜 8 曲（ギターの `treble_8` を含むバンド譜 2 曲、ピアノ、和音、加線、2 声、歌、連符）で比べた。新しい規則の読み手 ＋ 今日の lysc（今朝 7:33 のビルド、オクターブの変更 `05476d3bf` の後）の報告は、古い規則の読み手 ＋ 10/26 の lysc の報告と 1 行も違わない。
- **生成器の描き直しも前と同じ**: OmrGen をバンド譜 4 曲・ピアノ 4 曲で新しい規則で書き、今日の lysc で描いて読んだ。古い規則の OmrGen ＋ 10/26 の lysc と、読めた音の数がすべて同じだった。
- **手書きの正解**: Bohemian の手書きの正解（`data/bohemian/truth.md`）は新しい印に書き換えた。exact は 99.8% のまま。
- 正解の `.notes` は MIDI 番号なので、書き換えはない。

## 気づいたこと（オクターブとは別、依頼ではない）

- 生成譜のバンド譜（`out/gen-band`、10/20 の lysc で描いた台）を 10/26 以降の lysc で描き直すと、OMR の読みが下がる（4 曲で 1452 → 1087/1452）。ベースとギターの小節が丸ごと抜け、歌に全音符が足される。10/26 の lysc でも今日の lysc でも同じなので、10/20〜10/26 の Lily# の変更（コード名の行、TAB など）に OMR が合っていない。OMR 側で調べる。
  - **追記（2026-10-28 午後）: OMR 側の見立て違いだった。** 10/26 の lysc で描いても 1452/1452 のまま。下がったのは、10/20 に古い印（裸の `c` = C4）で書いた台の `.lys` を、今日の lysc（`c'` が中央の C）で描いたため（1 オクターブ低く描かれて正解とずれる）。今の OmrGen で作り直した台は、今日の lysc で元と全く同じ数字になる。Lily# 側の変更に問題はない。
