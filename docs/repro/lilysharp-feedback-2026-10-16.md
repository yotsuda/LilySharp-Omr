## 1. 小節が 1 つの音価で書けない拍子の全休符・複数小節の休み

**再現**: `docs/repro/mmrest-odd-meter-2026-10-16.lys`

```lys
title ""
time 5/4
key c major
octave absolute

part a { clef treble }

section A {
  a { c'4 d' e' f' g' | R4*5 | c'4 d' e' f' g' | R1*5/4 | c'4 d' e' f' g' | R4*40 | c'4 d' e' f' g' | }
}

form { ~A |. }
score { staff a }
```

**今の動き**（4/4・3/4・6/8・12/8・7/4 の `R1*N`・`R2.*N`・`R1.*N`・`R1..*N` は正しい。崩れるのは 5/4・9/8・5/8・7/8 など、1 小節が 1 つの音価や付点の音価で書けない拍子だけ）:

| 書き方 | 診断 | 描かれる物 |
|---|---|---|
| `R4*5` | `warning LYS2001: Measure duration 1/4 is less than time signature 5/4` | 1 小節に 4 分休符が 5 つ（小節の数は合う） |
| `R1*5/4` | なし | 3 小節にわたって 2 分休符が散らばる（2 分休符 2 つ、2 つ、2 分休符 1 つとスラッシュ）。小節の数が増える |
| `R1*10/4` | なし | 同じく、2 分休符の小節が並び、最後にスラッシュ |
| `R4*40`（5/4 の 8 小節） | `LYS2001` | 4 分休符 5 つの小節が 8 つ、その後に**空の小節が 32 個**（24 小節の曲が 56 小節に） |
| `R1*5/4*2` | `error LYS0030: '*' is not something a music block can hold` | 構文エラー |
| `R8*20`（5/4 の 2 小節。`c'4 d' e' f' g' \| R8*20 \| c'4 d' e' f' g' \|`） | `LYS2001`（`1/8`） | 8 分休符 10 個の小節が 2 つ（ここまでは小節の数が合う）、曲の後に**空の小節が 18 個** |

`*N` が「その音価の休符を N 個並べる」か「長さを N 倍した 1 つの休符」かがはっきりせず、乗数が分数のとき・小節の長さと合わないときに崩れているように見えます（推測です）。

**期待（LilyPond と同じ）**:
- `R4*5` と `R1*5/4` は、どちらも 5/4 の 1 小節の休み。小節の中央に全休符 1 つ。
- `R4*40`（と `R1*5/4*8`）は 8 小節の複数小節の休み。教会式の休符（長休符 2 つ）と、五線の上に数字の 8。
- `R1*5/4*2` は受け付ける（LilyPond は乗数を重ねて書ける）。少なくとも `R4*5N` の形が正しく描ければ OMR 側は足ります。

**OMR への影響**:
- OMR の `.lys` の書き出し（`OmrProto/Program.cs` の `FullRest`）は、こういう拍子の全休符を `R4*5`、N 小節の休みを `R4*5N`（9/8 なら `R8*9N`）と書きます。今は OMR が読んだ `.lys` を lysc で描き直すと、その小節が崩れます。
- 生成器は回避しています: `OmrGen/Gen.cs` の `AddMultiRests` が、小節が 1 つの音価で書けない拍子では休みを入れない（`if (!Representable(p.At(pos).BarTicks)) continue;`）。**直ったら、この行を外して評価台を作り直す**ので、直したことを教えてください。

## 2. 最初の段の休みの数字が題名にぶつかる

**再現**: `docs/repro/mmrest-count-under-title-2026-10-16.lys`（OmrGen の ties の 3 曲目、seed 7）。`lysc png --scale 5.6` で描くと、2 小節目の `R2.*4` の数字「4」が題名「ties003」の字に触れています。

同じことが起きた生成譜（seed 7、`--mmrests`、生成器の回避を入れる前）:
- `ledger004`: 数字「2」が題名の「l」に触れる（2 値の画像で 1 つの塊になる）
- `meters010`: 数字「11」が題名の「m」に重なる
- `ties003`: 上の再現ファイル

**今の動き**: 最初の段は、五線の上に何も無いものとして題名の下に置かれているように見えます。複数小節の休みの数字（五線の上、拍子の数字と同じ書体で約 2 間隔）が、段の中央あたり（題名の真下）に来ると題名とぶつかります。
`docs/repro/multibar-rests-2026-10-14.lys` が `title ""` にしてあるのも同じ理由です（「a title over the first system touches the 3 of the first rest」）。

**期待（LilyPond と同じ）**: 題名と最初の段の間は、段の上に出る物（休みの数字、速度記号、強弱、練習番号など）の高さも含めて空ける。数字と題名は触れない。

**OMR への影響**: 数字が題名と 1 つの塊になると OMR は数字を読めず、休みを 1 小節と数えて、以降の小節番号が全部ずれます。
生成器は回避しています: `AddMultiRests` が 2〜6 小節目に休みを入れない（`rng.Next(6, bars)`）。**直ったら `rng.Next(1, bars)` に戻す**ので、教えてください。
ほかの物（速度記号の付いた最初の音符の上の強弱など）でも同じ重なりが起きるかは調べていません。

## 3. 大譜表で、もう一方の五線で何も始まらない時刻の松葉が別の列から描かれる（2026-10-14 から）

**再現**: `docs/repro/hairpin-start-grandstaff-2026-10-14.lys`（ファイル冒頭のコメントに詳しく）

- 大譜表の左手の音符から始まる松葉で、その時刻に右手で何も始まらない（右手が休んでいる・長い音を持っている）と、松葉の始まりがその音符ではなく別の列（段の頭や、右手で何かが始まる次の時刻）になる。
- 例: 2 小節目の最後の音符（`fis,,16`、SVG の x 96.15）の crescendo が x 4.48（段の頭）から 101.43 まで描かれる。期待は 96.15 から。
- 右手を左手と同じリズムにすると正しい。1 つの五線だけでも正しい。
- OmrGen の曲（seed 7、`--marks`）では数間隔ずれる程度: piano006 の 3 小節 `gis,8@cresc` が 45.17 の音符に対して 31.40 から、piano002 の 14 小節 `fis,,16@cresc` が 53.55 の音符に対して 50.83 から。

**OMR への影響**: OMR は松葉の左の端からその最初の音符を決めるので、松葉が別の音符に付きます。きれいな台の松葉の残りの誤り 2 件がこれです。
